\section{Introduction}


\subsection*{Motivation}

{We face time series problems daily in real life. For example, in hospitals, doctors monitor patient heartbeats; in industry, machine sensors check machine health; and on the web, traffic is tracked to see user behavior. Time series data is everywhere, and it is important to classify it correctly.}

{Modern deep models are often black boxes. A major problem is that they cannot explain their answers. If they predict a specific class, they should be able to show the reason for it.}

{There are many techniques to explain deep models, such as SHAP, LIME, and Saliency. However, the issue is that they only run after the model makes a prediction. They also take a lot of time to run and sometimes do not give the true reason for the prediction. Therefore, it is better to have a model that can explain itself \citep{ribeiro2016lime, lundberg2017shap, rudin2019stop}.}

{For our baseline, we chose \millet{} as the starting point \citep{early2024millet}, which gives a built-in explanation. The problem was that while the explanation was decent, the model size was very large at 424k parameters. This makes it hard to use in Microcontroller Unit (MCU) applications. In contrast, the MLPerf Tiny Benchmark \citep{banbury2021mlperftiny}, uses a baseline model with 38.6k parameters, which is a very good size. They achieved 92\% accuracy after quantization (a technique used to reduce model size) without hurting the accuracy. However, their model does not have an interpretation feature, which I will explain in this report.}




{In summary, the \millet{} paper provides both classification and interpretability but has a large size. On the other hand, the MLPerf Tiny Benchmark provides a small micro-model but only gives classification predictions. We tried to solve both issues together in a single model. We tested different encoders with pooling techniques and finally created the SeaNet model. Its size is 41K parameters before quantization, and it provides better explanations. This makes it a great fit for MCU applications.}

\begin{contribution}
The work described in this report is my own, unless a paragraph is explicitly
marked as existing work. My main contributions are:
\begin{itemize}\itemsep3pt
  \item \textbf{The \seanet{} encoder family.}
  I designed compact encoders for feature extraction using TCN variants:
  depthwise-separable convolution, bottleneck, gated and input-gated blocks,
  spike/trend branches, multi-scale channels, and pyramid structures
  (\Cref{sec:architecture}).

  \item \textbf{Seven new MIL pooling heads.}
  I developed improved pooling heads inspired by conjunctive pooling:
  \texttt{classwise\_conjunctive},
  \texttt{softmax\_conjunctive},
  \texttt{adaptive\_classwise},
  \texttt{topk\_conjunctive},
  \texttt{attention\_max},
  \texttt{gated\_attention},
  and \texttt{dualstream\_conjunctive}.
  Each targets a weakness of \millet{} conjunctive pooling
  (\Cref{sec:pooling}).

  \item \textbf{A modular, config-driven benchmark.}
  I created configuration files that work as a pipeline. By just changing the settings, we can get different results. For example, we can use Optuna to fine-tune an encoder and pooling pair to find the best parameters, and then use those for final training. We also use MLflow to track the experiments. My contribution is providing a template so that any new encoder or pooling module can easily integrate into the whole pipeline with less effort.
\end{itemize}
\end{contribution}
