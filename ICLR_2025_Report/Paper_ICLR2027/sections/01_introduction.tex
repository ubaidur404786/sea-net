\section{Introduction}
\label{sec:intro}

A time series classifier is often not the end of the pipeline but the input to a decision. A
vibration monitor that reports \emph{bearing fault} is only useful if an engineer can see which part
of the recording caused that decision; a wearable that reports \emph{arrhythmia} can only be checked
if the beats it reacted to can be inspected. Post-hoc attribution \citep{ribeiro2016lime,
lundberg2017shap, sundararajan2017ig} is one way to do this, but it needs a second computation on top
of the classifier, and it explains a stand-in model rather than the model itself.
\citet{rudin2019stop} argues for the other way: build the explanation into the model, so that what is
explained is what is predicted.

The devices that need this most are the ones least able to afford it. Condition monitoring, wearable
health sensing and structural monitoring run on microcontroller-class hardware, where a common
setting is a few hundred kilobytes of SRAM against about one megabyte of flash \citep{lin2020mcunet,
banbury2021micronets}. A model can run there only if its weights fit in flash, its activations fit in
SRAM, and its computation fits in the energy available between two sensor readings. In this setting,
parameter count and FLOPs per series are not extra columns in a table; they decide whether the method
can be used at all.

\millet{} \citep{early2024millet} is our starting point, because it already gives both outputs we
want. It treats a series as a \emph{bag} of time steps and applies multiple instance learning
\citep{dietterich1997mil, ilse2018attention}: an encoder produces one embedding per time step, an
attention branch decides where to look, a per-step classifier decides what each position argues for,
and the product of the two is both summed into the prediction and read out directly as the
interpretation. The explanation is not an approximation of the model --- it is a value computed
inside the forward pass. \millet{} is also accurate, matching or beating standard deep time series
classifiers on the \ucr{} archive \citep{dau2019ucr}.

The cost, however, comes from the backbone and not from the MIL part. \millet{}'s reference setting
uses InceptionTime \citep{fawaz2020inceptiontime}: 423{,}707 parameters and 848\,MFLOPs for one
series of length 1008, so at \mbox{32-bit} precision the weights alone take about 1.6\,MB --- more
than the flash budget above, before activations, runtime or application code. Nothing in MIL requires
this. Swapping \millet{}'s interpretable head for ordinary global average pooling on the same
backbone removes only 1{,}041 of those parameters (\Cref{sec:method:mil}): the ability to explain
itself costs a quarter of a percent of the model, and almost all of the cost is the encoder. This
paper builds on that observation.

We therefore keep the MIL setup and change the two parts that decide its cost and how selective it
is. First, the encoder: a stack of multi-scale depthwise-separable dilated convolutions, which keeps
the length unchanged so that one embedding per time step reaches the head, and in which the pointwise
$1\times1$ mixing --- which holds most of the parameters once the convolutions are separable --- is
split into two smaller matrices through a narrow bottleneck of width $r = d/4$, halving that term.
Second, the pooling head: instead of averaging the evidence over all $T$ time steps behind one shared
attention gate, we score each class separately and average only the $k = \lceil \kappa T \rceil$
largest evidence values for that class. Both parts already exist --- separable convolutions
\citep{chollet2017xception, howard2017mobilenets}, squeeze-and-expand bottlenecks
\citep{he2016resnet, iandola2016squeezenet, sandler2018mobilenetv2}, and $k$-max selection in MIL
\citep{durand2016weldon} --- and we claim neither as new. What is new is putting them together inside
an interpretable MIL time series classifier, and measuring what that combination keeps and what it
gives up.

It keeps a lot and gives up something real. The resulting model uses 41{,}324 parameters and
76.7\,MFLOPs per series, $10.3\times$ and $11.1\times$ below \millet{}. On \webtraffic{}, the one
dataset here whose generator records which time steps actually carry the class signal, it beats the
equally-trained baseline at both jobs at once --- accuracy $0.947$ against $0.887$, \ndcg{} $0.772$
against $0.677$ (\Cref{fig:teaser}). Across 85 \ucr{} datasets it is worse: $0.810$ against $0.827$
for that baseline and $0.843$ for \millet{}'s published recipe. We show where that loss comes from
instead of hiding it in an average: a wide version of the same encoder, at 269\,K parameters, reaches
$0.829$ and ranks above the equally-trained baseline, so the price is paid for the smaller size and
not for a flaw in the design.

\paragraph{Contributions.}
\begin{itemize}
  \item \textbf{A MIL encoder small enough to be a candidate for small devices}
        (\Cref{sec:method:enc}): multi-scale depthwise-separable dilated convolutions with a
        bottlenecked pointwise mix, keeping the length unchanged so that the per-time-step
        interpretation is not lost, at $10.3\times$ fewer parameters and $11.1\times$ fewer FLOPs
        than \millet{}.
  \item \textbf{Per-class Top-$k$ conjunctive pooling} (\Cref{sec:method:head}), which adds no
        parameters and becomes \emph{exactly} the baseline head at $\kappa = 1$
        (\Cref{prop:topk}) --- the property that makes the $\kappa$ study of \Cref{sec:res:ablation}
        a controlled experiment rather than a comparison of two different models.
  \item \textbf{An ablation} separating the two changes (\Cref{sec:res:ablation}): the bottleneck
        buys the size reduction with no accuracy cost we can measure, and \mbox{Top-$k$} buys the
        interpretation quality, measured against per-time-step ground truth.
  \item \textbf{A warning about the AOPCR measure} (\Cref{sec:res:aopcr}): AOPCR has no fixed scale,
        and with the architecture and the code held fixed it changes by $5.2\times$ when only the
        training budget changes, so we compare only against baselines we retrained ourselves.
\end{itemize}

\noindent We do not run the model on a microcontroller and report no on-device latency, energy or
memory: our cost evidence is parameter counts, FLOPs counted by hand from the layer shapes, and GPU
timings. This shows the model \emph{could fit} such a budget, not that we ran it there. We also do
not claim state of the art on \ucr{}; \Cref{sec:res:ucr} measures what we give up instead of playing
it down.
